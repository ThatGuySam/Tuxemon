# Chromatic Connected Dialogue Firmware Prototype

**Build artifacts only. The experimental image is NOT approved for device installation.** It exceeds the stock 1 MiB application partition and requires a partition-table write. A separate layout/recovery review and explicit physical-installation approval are required before using it on a Chromatic.

The official stock baseline, the modified default-disabled build, and the enabled experimental build compiled successfully against ESP-IDF v5.3. No serial port was opened, radio command executed, firmware flashed, cartridge changed, or physical recovery attempted during this firmware work.

## What Was Built

`connected-demo.patch` applies to the official MCU repository at commit `e03a6baeec49cceda38057d5aed4ae006624c698`. It adds an optional C module that uses the existing LVGL/QSPI menu display and FPGA button path. Extending the existing C firmware keeps its display, settings, and board communication interfaces in place; replacing them in Rust would require a separate hardware migration.

The feature defaults to disabled. Even an enabled build starts with its panel and radio off. The module provides explicit scan, connect, disconnect, and private serial provisioning commands. The NPC panel offers `greet`, `rockitten`, and `farewell`; authored dialogue is available without a network connection.

Offline dialogue comes from the fork's `mods/tuxemon/l18n/en_US/LC_MESSAGES/base.po`: greeting is an excerpt of `professor_dialog` with line breaks joined as spaces, Rockitten uses the complete `professor_dialog6.2` entry, and farewell uses the complete `professor_dialog7` entry. Original contractions are preserved.

The HTTPS client posts to the local companion's `/v1/dialogue` route with a paired bearer secret. It validates the configured CA, server hostname, and certificate dates. Requests are refused until SNTP synchronization succeeds. The client refuses redirects, times out after 10 seconds, caps the response body at 2 KiB, and accepts at most 320 printable ASCII text characters with the exact request ID. Failed or unavailable requests use authored text. UI changes occur through a queue consumed by the LVGL task; replies from an earlier scene/intent generation are discarded. The panel labels replies as `host` or `offline`, without claiming that every host reply was generated by a model.

In the experimental enabled build, `pwrmgr.c` unconditionally vetoes the stock manual light-sleep path before any FPGA or OSD sleep preparation. **The MCU stays awake even when the panel and radio are off.** Battery cost is unmeasured; normal sleep integration is deferred. The feature-disabled build preserves the original stock sleep path. Closing the panel does not silently disconnect an active network; network-off still stops the radio.

Dialogue uses a fixed wrapped viewport with explicit pages. The renderer calculates each page using LVGL's actual font, letter spacing, line spacing, and content dimensions through `lv_txt_get_size`; no character-per-page capacity is assumed. A advances the remaining pages before requesting another reply. Changing the intent starts a fresh conversation. Display behavior remains unverified on hardware.

## Provisioning Contract for Future Hardware Testing

After separately approved installation and recovery preparation, the existing 115200-baud MCU console exposes:

- `tux_demo on` or `tux_demo off`: enable or close the NPC panel. The physical Menu button still controls FPGA overlay visibility. Up/Down selects an intent. A advances pages, then requests another reply after the final page. A can request immediately after a new intent is selected. B closes the panel.
- `tux_network scan`, `tux_network connect`, `tux_network off`: run one explicit wireless action. There is no automatic retry/reconnect. Scan leaves the radio enabled until `off`.
- `tux_config`: the command handler reads one bounded raw JSON line directly from the console UART. Its implementation avoids echo/history, consumes oversized input through its newline, and performs a bounded drain plus flush before returning to the REPL. Physical no-echo behavior and delayed-tail handling remain unverified. Send the packet only after its ready message; the receive window lasts 30 seconds. Required keys are `ssid`, `password`, `endpoint`, `pairing_secret`, and `ca_pem`. Credentials belong in a private local provisioning flow, never chat or source control.
- `tux_forget`: while the network is off and worker idle, clear the volatile prototype configuration.

SSID is capped at 32 bytes, password at 64, HTTPS endpoint at 192, pairing secret at 16–128 printable ASCII characters, and CA PEM at 2,048 bytes. The companion certificate's hostname must match the endpoint. The endpoint includes `/v1/dialogue`. Station connection starts SNTP. HTTPS requires a successfully synchronized clock, with `CONFIG_MBEDTLS_HAVE_TIME_DATE=y` enabling certificate validity checks. Failed time synchronization uses authored dialogue without making the HTTPS request.

Configuration is **RAM-only**. Reprovision Wi-Fi credentials, endpoint, pairing secret, and certificate after every reboot. The Wi-Fi driver uses `WIFI_STORAGE_RAM`; this prototype reads or writes no credential NVS keys. Firmware does not print credentials, and configuration has no compiled-in passwords or account tokens. This deliberate disposable state keeps hardware credentials out of plaintext flash. Important account authorization and generated dialogue snapshots remain durable in the host companion.

## Remaining Qualification

Compilation verifies the C/ESP-IDF/LVGL interfaces, linkage, and the selected partition size guard. It does not verify antenna implementation, RF performance, available heap under TLS, on-device pagination, physical buttons, private serial provisioning, reprovisioning after reboot, Wi-Fi reconnect, battery draw, or recovery after a bad image. Those checks require the actual device and the separately approved installation/layout plan. Normal sleep is deferred in enabled firmware.

The official [MCU source](https://github.com/ModRetro/oss-chromatic-console-mcu) documents ESP-IDF builds and its composite USB serial interface. [MR Updater](https://support.modretro.com/en_us/chromatic-firmware-updater-ryhoYnzCx) is the official firmware update path. Its documented existence does not establish a tested recovery path for an arbitrary changed partition layout on this unit.
